## 1. Зачем

Аудит 13.11.2026 по claudebot (31 день журналов сессий):

- `test-engineer` и `ui-tester` не вызывались ни разу (devils-advocate — 40, researcher — 36, developer — 15).
- Полный e2e-набор проекта (`npm run test:e2e`) не запускался ни разу; наборы за флагами (`test:canary`, `test:live-sdk`) — тоже. Сами e2e рабочие: ручной прогон 31 passed / 3 skipped / 0 failed за 2,6 мин.
- Оговорка: правок интерфейса веб-чата за период было всего две, так что в claudebot «0 запусков» — слабый замер. Богдан видит то же в других, более «интерфейсных» проектах — ради них релиз в первую очередь.

## 2. Что получится

В проекте с **контрактом** (блок в `CLAUDE.md`, §5.2) сабтимс работает как CI/CD:

1. сам находит наборы тестов и прогоняет их через `subteams-tests run` — так фиксируется, какое именно содержимое проверено и с каким кодом выхода;
2. правка логики → test-engineer пишет адверсариальные тесты и прогоняет их; правка интерфейса → ui-tester прогоняет существующие e2e, **смотрит на изменённые экраны глазами агента через agent-browser, снимает скриншоты** и пишет список «что доработать»;
3. **не даёт закоммитить**, пока содержимое коммита не совпадает с проверенным: наборы — зелёные на этом содержимом, агенты — отработали на нём или на версии, отличающейся не больше порога мелочи (R9).

В проекте **без контракта** то же самое работает, кроме блокировки: гейт **предупреждает модель и пользователя** («интерфейс застейджен, проверки не было», «проверенного прогона e2e нет», «последний прогон e2e упал»). Новый проект, созданный через сабтимс, получает контракт при создании; в существующем сабтимс один раз предлагает его добавить.

## 3. Решения

| # | Решение | Почему |
|---|---------|--------|
| R1 | Два слоя UI-проверки: **Playwright Test** (регрессия, тесты в репозитории) + **agent-browser** (живой осмотр агентом со скриншотами) | Без регрессии сломанное однажды ломается снова, без осмотра агент не видит результат |
| R2 | agent-browser, а не PinchTab и не Playwright MCP | PinchTab — фоновый сервер, заточен под парсинг и антибот, дешевле agent-browser лишь на 10-20%; Playwright MCP — дорогой и у Богдана регулярно не поднимается |
| R3 | agent-browser ставится сам при первом вызове — из lock-файла плагина через `npm ci --ignore-scripts` (сверка sha512, без скриптов установки) в кэш `~/.cache/claude-subteams/agent-browser/<версия>/`. Браузер — **системный Chrome**; нет его → осмотр честно не выполняется + подсказка `subteams-browser setup` (единственное место, где качается Chrome) | Спайк 0.3: `npm ci --ignore-scripts` ставит рабочий бинарь, контрольные суммы есть в lock. Спайк 0.4: системный Chrome подхватывается сам; Chromium из кэша Playwright на этой машине требует `--no-sandbox` — снижение защиты, поэтому не используем |
| R4 | Любое падение набора тестов блокирует сдачу. «Тест был красным и до нас» — решает Богдан | Базовый прогон в отдельном worktree неработоспособен (нет `node_modules`, сборки, браузеров) |
| R5 | Осмотр через agent-browser — на каждую правку интерфейса выше порога мелочи (Standard и Full) | Основная работа идёт в Standard |
| R6 | Жёсткий гейт только при контракте; без контракта — предупреждения модели и пользователю | Эвристика без контракта дала бы ложные блокировки (в claudebot за месяц 6 из 7 коммитов с `.html/.css` — КП, презентации, обложки) |
| R7 | Хвосты claudebot (e2e в гейте `self-restart.sh`, еженедельный canary) — после релиза; **контракт для claudebot** — в рамках релиза, до приёмки E8 | Без контракта гейт в claudebot не включится |
| R8 | test-engineer на гейте: изменённая логика в проекте с контрактом требует его квитанции | Богдан: «протестировали, проверили, потом в коммит — как CI/CD» |
| R9 | **Порог мелочи = допустимый дрейф после последней проверки агентом**: если содержимое коммита отличается от проверенного агентом не больше чем на 10 строк в 2 файлах (без новых, удалённых, переименованных, бинарных) — новый вызов агента не нужен. Считается **накопленно** от последней проверки, поэтому дробление коммитов не помогает. Наборы тестов освобождения не получают никогда. В контракте порог можно только уменьшить | Богдан: «сделай порог мелочи»; раунд 2: порог «на коммит» обходится серией мелких коммитов и не видел `commit -a` |
| R10 | Квитанция = **снимок содержимого** (git-дерево файлов на момент проверки), а не время и не текст команды. Гейт сравнивает его с деревом, которое уйдёт в коммит | Раунд 2 (все трое): время изменения файлов не видит частичный стейдж, удаления, переименования; совпадение по тексту команды подделывается (`npm test || true`); привязка к сессии пропускает чужой репозиторий |
| R11 | Гейт читает контракт из **последнего коммита (HEAD)**. Правка контракта — только отдельным коммитом, без других файлов, с видимым пользователю предупреждением | Иначе модель ослабляет гейт в том же коммите, который гейт проверяет |

## 4. Не делаем (non-goals) и честные остатки

- Свой тест-раннер. Плагин находит и вызывает то, что в проекте есть.
- Молчаливая установка Playwright в проект. Нет Playwright Test — ui-tester спрашивает. Исключение — создание нового проекта по просьбе пользователя (`project-scaffold`): там Playwright ставится явно, как часть заказанного проекта.
- Автозапуск наборов `opt-in` и `live` (ключи, сеть, деньги) — только называются в отчёте пропущенными.
- PinchTab-бэкенд, кросс-браузер, a11y-аудит, метрики производительности.
- **Остатки, которые релиз НЕ закрывает (в ADR):**
  - без контракта — проза + видимые предупреждения;
  - гейт проверяет, что агент отработал на этом содержимом с итогом pass и оставил доказательства (прогоны наборов, скриншоты), а не качество его работы — та же осознанная грубость, что у гейта ревью;
  - гейт — ограничитель модели в Bash, а не защита репозитория: коммиты руками, из IDE, через MCP он не видит; квитанции лежат в кэше пользователя, и намеренную подделку файлов квитанций он не ловит;
  - в claudebot код уходит в прод через `self-restart.sh` до коммита (хвост R7);
  - если хук убит по таймауту, Claude Code продолжает без него — дорогие проверки поставлены после дешёвых, бюджет хука 60 с.

## 5. Архитектура

### 5.1 Поток (using-subteams §6.7 — единственное описание)

```
 правка ──▶ ревью (как сейчас) ──▶ правка логики выше порога? ──▶ test-engineer
                                   правка UI выше порога?     ──▶ ui-tester
                                        (порядок: ui-tester → test-engineer)
           ──▶ финальный  subteams-tests run --all-auto   ──▶ git commit
                      │                                          │
   квитанции: suite (run), browser (скриншоты),        pre-commit-gate:
   ui/te (SubagentStop + доказательства)               дерево коммита vs деревья квитанций
```

### 5.2 Контракт проекта v1

Опциональный блок в `CLAUDE.md` (если нет — в `AGENTS.md`; при наличии в обоих берётся `CLAUDE.md`). Маркер распознаётся только в начале строки и **вне** блоков кода (примеры в документации контракт не включают). JSON — потому что `jq` хукам уже нужен.

````markdown
<!-- subteams:test-suites v1 -->
```json
{
  "suites": [
    {"name": "unit", "cmd": "npm test", "kind": "unit", "run": "auto", "paths": ["src/**"]},
    {"name": "e2e",  "cmd": "npm run test:e2e", "kind": "e2e", "run": "auto"},
    {"name": "smoke-live", "cmd": "npm run test:live", "kind": "integration", "run": "live"}
  ],
  "ui_globs":   ["src/ui/**", "public/**"],
  "ui_exclude": ["public/emails/**"],
  "code_globs": ["src/**"],
  "test_globs": ["**/*.test.*", "**/*.spec.*", "tests/**", "e2e/**"],
  "app": {"url": "http://localhost:3000", "start": "playwright-webServer"},
  "small_change": {"max_lines": 10, "max_files": 2}
}
```
<!-- /subteams:test-suites -->
````

- `kind` — тип (`unit|integration|e2e`); `run` — политика (`auto` гнать всегда; `opt-in` по явной просьбе; `live` никогда автоматически).
- `paths` — когда набор обязателен для коммита; **без `paths` набор обязателен для любого коммита, задевающего не-docs файлы** (docs-класс — общий с гейтом ревью, `NEUTRAL_RE`).
- `ui_globs`/`ui_exclude` — интерфейс для ui-tester; `code_globs` — логика для test-engineer (нет поля → не-docs файлы вне `ui_globs` и `test_globs`; `--init-contract` всегда пишет его явно).
- `test_globs` — тестовые файлы: **не** входят в группы ui/code при проверке дрейфа (иначе тест, написанный test-engineer'ом, обесценивает квитанцию ui-tester и наоборот), но входят в наборы.
- `app.start` — только `playwright-webServer` или `none` (приложение уже доступно по `url`). Произвольных команд старта плагин не исполняет (в claudebot второй запуск бота убивает прод через pid-файл).
- `small_change` — только уменьшение относительно встроенного потолка 10/2.
- **Маркер отказа:** `<!-- subteams:test-suites none -->` — «контракт не нужен», сабтимс больше не предлагает его добавить.

Схема живёт **в одном месте** — скилл `claudemd-engineering`; `templates/claudemd-snippet.md` — одна строка-ссылка; README и ADR ссылаются. Устаревшая копия сниппета в `scripts/install.sh:101-107` — убрать или синхронизировать.

### 5.3 Квитанции (R10)

Хранилище: `${XDG_CACHE_HOME:-$HOME/.cache}/claude-subteams/receipts/<repo-id>/`, `repo-id` = sha1 канонического `git rev-parse --git-common-dir` (worktree одного репозитория делят квитанции — корректность обеспечивает сверка содержимого, а не изоляция). Запись атомарная (временный файл + `mv`). Чистка квитанций старше 14 дней — при каждой записи (прецедент `subagent-rails:57`).

**Снимок** = git-дерево рабочего каталога: `GIT_INDEX_FILE=<tmp> git read-tree HEAD && git add -A && git write-tree` (учитывает новые, удалённые, переименованные файлы и `.gitignore`; реальный индекс не трогается).

| Квитанция | Кто пишет | Поля |
|-----------|-----------|------|
| `suite` | `subteams-tests run <suite>`: снимок до прогона и после; исполняет `cmd` **из контракта HEAD** (без контракта — из обнаружения) с `cwd`, ловит настоящий код выхода; изменилось содержимое во время прогона → квитанция помечается `dirty` и не засчитывается | `suite, cmd_sha, contract_sha, exit, tree, t_start, t_end` |
| `shot` | `subteams-browser screenshot`: путь и размер файла | `path, session, ts` |
| `ui` / `te` | хук SubagentStop для `claude-subteams:ui-tester` / `claude-subteams:test-engineer` (канонический матч имени: `== ui-tester` или оканчивается на `:ui-tester`) | `status, tree, t_start, t_end, evidence` |

**Статус агента** (спайк 0.6): из `last_assistant_message`; если поля нет (режим завершения через `SubagentHandback`) — из `input.message` последнего вызова `SubagentHandback` в `agent_transcript_path` (опрос до 2 с — транскрипт дописывается после хука); первая непустая строка вида `Status: <слово>`; не разобрали → квитанции нет.

**Доказательства** (статус сам по себе не верим): `ui` со статусом `pass` засчитывается, только если в интервале `[t_start, t_end]` агента есть ≥2 квитанции `shot` и — если существует `run:auto` e2e-набор, чьи `paths` покрывают хотя бы один UI-файл коммита (набор без `paths` покрывает всё) — ≥1 квитанция такого набора с `exit 0`; `degraded` — то же условие по e2e, скриншотов нет, причина в итоге. (Уточнено после оценки промптов: иначе ui-tester, честно не гоняющий непокрывающий набор, попадал в петлю.) `te` со статусом `pass` — ≥1 квитанция `suite` с `exit 0` в интервале. `t_start` пишет хук SubagentStart.

### 5.4 Гейт коммита

Дешёвые проверки первыми:
1. Команда — `git commit` (существующий разбор `lib-gitcmd.sh`). Нет — выход.
2. Контракт в HEAD целевого репозитория — `git show HEAD:CLAUDE.md | grep` маркера **без `jq`**. Есть маркер, а `jq` нет → `deny` «поставь jq» (§9.7). Контракта в HEAD нет, но он есть в индексе → режим «новый контракт»: проверки как с контрактом, но `allow` + предупреждение (первый коммит контракта не блокируется его же правилами).
3. Контракт есть: формы `git commit -a` и `git add … && git commit` → `deny` «застейдж отдельно, потом коммит» (до индексации дерево коммита неизвестно — раунд 2, C1).
4. Дерево коммита = `git write-tree` реального индекса. Файлы коммита = `git diff --name-only HEAD <дерево>`.
5. Коммит меняет блок контракта → разрешён, только если в коммите нет других файлов; предупреждение пользователю «контракт тестов изменён: …».
6. Для каждой задетой группы — нужная квитанция:
   - набор (по `paths` или «любой не-docs»): квитанция `suite` этого набора, `exit 0`, не `dirty`, `contract_sha`/`cmd_sha` совпадают, и `git diff --quiet <tree квитанции> <дерево коммита> -- <paths набора>` (содержимое ровно то, что проверено);
   - `ui_globs` (минус `ui_exclude`, `test_globs`): самая свежая квитанция `ui` (`pass|degraded`, доказательства в порядке), и дрейф `git diff --numstat <tree> <дерево коммита> -- <группа>` ≤ порога, без A/D/R/бинарных; нет действительной квитанции агента — дрейф считается от **якоря**: когда группа впервые проходит как мелочь без квитанции агента, гейт записывает якорь = дерево HEAD; последующие мелкие коммиты якорь не двигают, поэтому дрейф накапливается (уточнено после оценки промптов: дрейф «от пустого дерева» требовал агента даже на правку в одну строку, что противоречило R9 и E10);
   - `code_globs` (минус `test_globs`): то же с квитанцией `te`.
7. Решение: контракт → `deny` со списком **всего** недостающего сразу; без контракта → `allow` + предупреждение. Текст отказа — «прогони using-subteams §6.7; обход только пользователем: `CLAUDE_SUBTEAMS_SKIP_TEST_GATE=1` в окружении, модель выставить не может». Порог в тексте отказа не называется.
8. Сбой при контракте (битый JSON контракта, нет `jq`, не загрузилась библиотека, ошибка git) → `deny` с причиной. Без контракта → `allow` + предупреждение. Отсутствие id сессии гейту больше не мешает (квитанции не привязаны к сессии).

**Предупреждения пользователю** (R10 Богдана, «чтобы прилетало»): `systemMessage` + `additionalContext` с шапкой «передай пользователю одной строкой» (как в `session-end-reminder` — видимость `systemMessage` из PreToolUse не гарантирована, проверка 0.8). Один JSON-объект на весь вывод хука вместе с существующими NOTES.

## 8. Риски и нюансы

**Риски**
- **Цена в автономной работе** (высокая вероятность, средний ущерб). В claudebot за месяц все 7 коммитов с кодом были выше порога → test-engineer, а при UI ещё и ui-tester, на каждом. Оценка: осмотр 2-5 мин и 20-50 тыс. токенов sonnet, e2e 2,6 мин. Решение владельца (R8, R5); замерить на приёмке, при перегрузке — поднимать вопрос порога.
- **Автоустановка — цепочка поставок.** Lock + `npm ci` (sha512) + `--ignore-scripts` + проверка версии + обновление только релизом плагина; `NO_AUTO_INSTALL`; Chrome только системный или явный `setup`.
- **Гейт заклинит работу** при контракте. Обход — пользователем; первую неделю смотреть на отказы; `subteams-tests status` показывает недостающее до попытки коммита.
- **Требование «застейдж отдельно»** (`commit -a` запрещён при контракте) меняет привычный поток модели — отказ гейта объясняет, как правильно.
- **Статус из транскрипта** при завершении через `SubagentHandback` читается с опросом; если формат хендбека изменится в CLI — квитанции не будет (безопасная сторона: отказ, не пропуск).
- **Снимок через временный индекс** на огромных репозиториях может быть медленным — бюджет хука 60 с; тест на 300 файлах.

**Неочевидное**
- `subteams-tests` запускает наборы только в режиме `run` по явному вызову; гейт ничего не запускает, только сверяет квитанции.
- Квитанции не привязаны к сессии: проверенное в одной сессии засчитывается в другой, если содержимое то же. Это корректно и убирает зависимость от id сессии.
- `degraded` пропускается гейтом — честная деградация лучше заклинивания; причина обязана быть в итоге.

**Зависимости:** `jq`, git, Node/npm (автоустановка), системный Chrome (или `setup`), agent-browser 0.43.0 и его скилл `dogfood`, Claude Code ≥ 2.1.284 (`bin/`, SubagentStart/Stop с `agent_transcript_path`).

**Откат:** плагин на тег 1.49.0; только гейт — `CLAUDE_SUBTEAMS_SKIP_TEST_GATE=1`; только автоустановка — `CLAUDE_SUBTEAMS_NO_AUTO_INSTALL=1`; в проекте — убрать контракт (режим предупреждений).
