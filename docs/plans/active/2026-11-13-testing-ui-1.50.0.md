## 2. Что получится

В проекте, где описано, какие тесты есть и что считается интерфейсом (блок-контракт в `CLAUDE.md`, §5.2), сабтимс:

1. сам находит наборы тестов и прогоняет все обычные (не за флагами);
2. после правки интерфейса зовёт ui-tester: тот прогоняет существующие e2e, **смотрит на изменённые экраны глазами агента через agent-browser** и, если уместно, дописывает автотест;
3. **не даёт закоммитить** правку, пока не пройден цикл как в CI/CD: нужные наборы прогнаны зелёными, test-engineer написал и прогнал адверсариальные тесты на изменённую логику, ui-tester проверил интерфейс — всё после последнего изменения этих файлов. Мелкие правки (порог, §5.4) освобождаются от двух агентов, но не от прогона наборов.

В проекте без контракта всё то же самое работает, кроме блокировки: гейт **предупреждает и модель, и пользователя** (видимое сообщение в Claude Code: «застейджен интерфейс, проверки не было» / «e2e не прогнан» / «e2e упал»). Эвристики без контракта слишком часто ошибаются, чтобы блокировать (§10, коммиты КП и презентаций). Новые проекты, созданные через сабтимс, получают контракт сразу при создании; в существующих сабтимс один раз предлагает его добавить (Задача 7).

Скриншоты — обязательная часть проверки интерфейса: ui-tester не только ищет поломки, но и оценивает экраны «что стоит доработать» (необязательный список, не блокирует), пути к скриншотам — в итоге.

## 3. Решения

Принятые Богданом 13.11.2026 («по твоим рекомендациям») — с поправками после защиты плана. Поправки помечены **⚠ изменено** и вынесены в вопросы §9.

| # | Решение | Почему |
|---|---------|--------|
| R1 | Два слоя UI-проверки: **Playwright Test** (регрессия, тесты в репозитории) + **agent-browser** (живой осмотр агентом) | Один слой не закрывает задачу: без регрессии сломанное однажды ломается снова, без осмотра агент не видит результат |
| R2 | agent-browser, а не PinchTab и не Playwright MCP | PinchTab — фоновый сервер с токеном, заточен под парсинг и антибот, дешевле agent-browser лишь на 10-20%; Playwright MCP — дорогой и у Богдана регулярно не поднимается |
| R3 ⚠ | agent-browser ставится сам при первом вызове в папку данных плагина — **из lock-файла плагина, `npm ci --ignore-scripts`** (проверка контрольных сумм, без скриптов установки). **Chrome сам не качается**: используется системный Chrome или браузер Playwright, а если нет ни того ни другого — осмотр честно не выполняется и пишется команда `subteams-browser setup` | Критики (Codex, Gemini, devils-advocate): `npm i пакет@версия` фиксирует только верхний пакет и исполняет postinstall, который в agent-browser умеет качать бинарь с GitHub без проверки хеша; Chrome — второй неподписанный артефакт на ~150 МБ из агентской сессии |
| R4 ⚠ | Любое падение e2e **блокирует** сдачу. Проверку «падал ли тест до нас» через отдельный worktree убираем | Все четыре критика: в свежем worktree нет `node_modules`, сборки и браузеров — тест упадёт по посторонней причине и тихо обойдёт блокировку. Если тест был красным и до правки — оркестратор говорит об этом Богдану, решает он |
| R5 | Осмотр через agent-browser — на каждую правку интерфейса (Standard и Full) | Основная работа идёт в Standard |
| R6 ⚠ | Гейт коммита **жёсткий только в проектах с контрактом**, в остальных — предупреждение. Гейт проверяет не «агент запускался», а **квитанции**: набор прогнан с кодом 0 / ui-tester вернул статус pass — и всё это **после** последнего изменения застейдженных файлов | Критики: (а) маркер «на старте агента» возвращает баг, исправленный в 1.49.0; (б) маркер без привязки ко времени пропускает правку, сделанную после проверки; (в) эвристика по расширениям дала бы ложные блокировки на 6 из 7 «интерфейсных» коммитов claudebot за месяц (КП, презентации, обложки) |
| R7 ⚠ | Хвосты claudebot — после релиза, **кроме блока-контракта для claudebot**: он нужен для приёмки и для того, чтобы гейт в claudebot вообще включился | Без контракта claudebot получил бы только предупреждения |
| R8 (Богдан, rev.3) | **test-engineer тоже на гейте**: «протестировали, проверили, потом в коммит» — как CI/CD. В проектах с контрактом изменённая логика (код вне docs) требует квитанции test-engineer со статусом pass | Без гейта test-engineer за месяц не вызывался ни разу — то же, что с ui-tester |
| R9 (Богдан, rev.3) | **Порог мелочи**: правка ≤ 10 изменённых строк в ≤ 2 файлах, без новых и удалённых файлов, освобождает от ui-tester и test-engineer (ревью и прогон наборов остаются). Порог настраивается в контракте | Автономная работа без порога = агент на каждую запятую; без агентов вообще = текущая проблема |
| R10 (Богдан, rev.3) | Ответы на §9: гейт жёсткий при контракте + видимые пользователю предупреждения везде; Chrome — имеющийся, `setup` явно; приёмка ≈ 15 сессий; контракт для claudebot — да; новый проект через сабтимс должен получать проверку интерфейса «из коробки» | — |

## 4. Не делаем (non-goals) и честные остатки

- Свой тест-раннер. Плагин находит и вызывает то, что в проекте есть.
- Молчаливая установка Playwright в проект. Нет Playwright Test — ui-tester спрашивает.
- Автозапуск наборов за флагами и «живых» (ключи, сеть, деньги) — только называются в отчёте пропущенными.
- PinchTab-бэкенд, кросс-браузер, a11y-аудит, метрики производительности.
- **Остатки, которые релиз НЕ закрывает (записать в ADR):**
  - в проектах без контракта всё держится на прозе + видимом предупреждении гейта;
  - гейт проверяет, что агенты отработали со статусом pass, а не качество их работы (та же осознанная грубость, что у гейта ревью);
  - гейт ловит коммиты через Bash модели; коммиты руками, из IDE, через MCP он не видит — это ограничитель модели, а не защита репозитория;
  - в claudebot код уходит в прод через `self-restart.sh` до коммита — гейт коммита этого не догоняет (хвост R7: e2e в гейте self-restart);
  - правки выше порога мелочи в проектах с контрактом проходят через ui-tester и test-engineer даже в Lightweight; обойти может только пользователь переменной окружения.

## 5. Архитектура

### 5.1 Поток

```
 правка ──▶ оркестратор (using-subteams §6.7 «Наборы проекта и UI»)
              │ 1. subteams-tests --diff <base>  → JSON: наборы, затронутые пути, UI?
              │ 2. гонит все наборы run=auto     ──▶ PostToolUse(Bash): квитанция набора
              │ 3. UI затронут → ui-tester                (имя, код выхода, время)
              │       ├ существующие e2e  (его Bash → те же квитанции, если хуки видят
              │       │                    вызовы субагента — проверяет спайк 0.5)
              │       ├ осмотр: subteams-browser --session <уникальная>
              │       └ новый тест (если уместно) / вопрос про Playwright
              │    SubagentStop(ui-tester) ──▶ квитанция UI: статус из итога агента
              ▼
 git commit ──▶ pre-commit-gate:
                 застейдженные файлы (тот же FILES, что у гейта ревью)
                 ├ попали в paths набора X → нужна квитанция X: exit 0, позже mtime файлов
                 └ попали в ui_globs       → нужна квитанция UI: pass|degraded, позже mtime
                 нет контракта → те же проверки по эвристике, но только предупреждение
```

### 5.2 Контракт проекта (межпроектный интерфейс, версия v1)

Опциональный блок в `CLAUDE.md` проекта (если нет — в `AGENTS.md`; при наличии в обоих берётся `CLAUDE.md`). JSON внутри — потому что `jq` хукам уже нужен, а markdown-таблицу в bash надёжно не разобрать (`|` в командах, обратные кавычки).

````markdown
<!-- subteams:test-suites v1 -->
```json
{
  "suites": [
    {"name": "unit",  "cmd": "npx vitest run",   "kind": "unit", "run": "auto"},
    {"name": "e2e",   "cmd": "npm run test:e2e", "kind": "e2e",  "run": "auto",
     "paths": ["webchat/**", "src/web/**"]},
    {"name": "canary","cmd": "npm run test:canary","kind": "integration","run": "opt-in"}
  ],
  "ui_globs":   ["webchat/src/**", "webchat/public/**"],
  "ui_exclude": ["webchat/public/antre/**"],
  "app": {"url": "http://localhost:18787", "start": "playwright-webServer"},
  "code_globs": ["src/**", "webchat/src/**"],
  "small_change": {"max_lines": 10, "max_files": 2}
}
```
<!-- /subteams:test-suites -->
````

Поля: `kind` — тип набора (`unit|integration|e2e`), `run` — политика (`auto` — гнать всегда; `opt-in` — только по явной просьбе; `live` — никогда автоматически). `paths` — когда набор обязателен для коммита (нет `paths` → обязателен всегда при `run=auto`). `ui_globs`/`ui_exclude` — что считается интерфейсом для осмотра и гейта. `app.start` — **только** `playwright-webServer` (поднять через `webServer` из конфига Playwright проекта) или `none` (приложение уже доступно по `url`); произвольных команд старта плагин не исполняет (devils-advocate: в claudebot второй запуск бота убивает прод через pid-файл).

`code_globs` — логика, для которой нужен test-engineer (нет поля → все не-docs файлы, кроме `ui_globs`-only правок вёрстки: `.css/.scss/.html`). `small_change` — порог мелочи (R9), по умолчанию 10 строк / 2 файла.

### 5.4 Порог мелочи

Считается по застейдженному диффу группы (`git diff --cached --numstat` по файлам группы): сумма добавленных+удалённых строк ≤ `max_lines`, файлов ≤ `max_files`, нет новых, удалённых и переименованных файлов, нет бинарных. Мелочь → не нужны квитанции ui-tester и test-engineer; квитанции наборов (`run=auto`, задетых `paths`) нужны всегда — прогон наборов дешёвый и детерминированный, а смена подписи кнопки — ровно то, что ломает отправку формы (сценарий E1).

Документация контракта — в `templates/claudemd-snippet.md` и скилле `claudemd-engineering` (это действующий интерфейс, а не только README). Доверие: команды из контракта = команды из `package.json` проекта, тот же уровень; security-auditor смотрит отдельно (Задача 10).

### Задача 1. `hooks/lib-testclass.sh` + `scripts/discover-tests.sh` + `bin/subteams-tests`

**Поиск наборов** (корень = `git rev-parse --show-toplevel` или cwd; `--root` перекрывает):
- контракт v1 из `CLAUDE.md`/`AGENTS.md` — главнее всего остального;
- без контракта: `package.json` scripts (`test`, `test:*`, `e2e*`) с учётом пакетного менеджера по lock-файлу (`pnpm-lock.yaml` → `pnpm`, `yarn.lock` → `yarn`, `bun.lockb` → `bun`, иначе `npm`); workspaces и `packages/*`, `apps/*` до глубины 3 (с полем `cwd`); `playwright.config.*`/`cypress.config.*` до глубины 3 (в claudebot конфиг лежит в `e2e/`); `pyproject.toml`/`pytest.ini`; `Cargo.toml`; `go.mod`; цели `test*`/`e2e` в `Makefile`;
- дедупликация: конфиг Playwright и скрипт `test:e2e`, указывающий на него, — один набор;
- эвристика политики без контракта: `RUN_*=` в команде, имена `live`, `canary` → `opt-in`; остальное `auto`. Результат помечается `"source": "heuristic"` — это подсказка, не авторитет.

**Классификация файлов** (`--files -` со stdin, либо `--diff <base>`): порядок явный — (1) docs-класс (`*.md`, `docs/**`, `LICENSE`…) исключается первым, как у гейта ревью; (2) `ui_exclude`; (3) `ui_globs` и `paths` наборов из контракта; (4) без контракта — эвристика **только по расширениям** (`.tsx .jsx .vue .svelte .astro .css .scss .sass .less .html`), сегменты путей (`app/`, `templates/`…) — нет (ложные срабатывания на бэкенде и письмах).

### Задача 3. ui-tester — три хода (prompt-engineer пишет, prompt-evaluator проверяет)

1. **Найти:** `subteams-tests --diff <base>`.
2. **Регрессия:** прогнать e2e-наборы из `recommend.run`. Любое падение → `Status: issues-found` (R4). Если ui-tester видит признаки «тест был красным и до правки» — пишет это в отчёт как наблюдение, статус не меняет.
3. **Осмотр:** приложение — только по `app` из контракта (`url` уже доступен или `webServer` Playwright-конфига) или по URL из брифа. Своих команд старта не придумывать; нечем поднять → «осмотр не выполнен: нет безопасного способа поднять приложение». Ход по образцу `subteams-browser --session <своя> skills get dogfood` (читать скилл, не пересказывать), только изменённые экраны, 320 и 1280, проверить: элементы на месте, текст не обрезан, формы работают, нет ошибок консоли. **Скриншоты обязательны** для каждого изменённого экрана на обоих размерах — по ним ui-tester (а) подтверждает, что всё на месте, (б) оценивает экран «что стоит доработать» (иерархия, отступы, читаемость, мобильная вёрстка) — отдельным необязательным списком, который не влияет на статус. Скриншоты — в папку данных плагина, не в дерево проекта (чтобы не уехали в `git add -A`); в отчёт — пути. Оркестратор показывает пользователю пути и список доработок в итоговом ответе. Закрыть **свою** сессию.
4. **Память:** новый тест — только если в проекте уже есть фреймворк e2e (Playwright, Cypress… — писать в нём, а не тащить второй) и поведение не косметическое. Иначе — строка «тест не добавлен: <почему>» и, если фреймворка нет, вопрос «поставить Playwright Test?». `npm init playwright@latest` удалить.
5. **Итог** — первой строкой машиночитаемо: `Status: pass | degraded | issues-found | blocked` (`degraded` = регрессия прогнана зелёной, осмотр не выполнен с названной причиной). Плюс секции `Regression`, `Exploratory review` (скриншоты), `Improvements` (что доработать, не блокирует), `New tests`. Этот статус читает хук для квитанции UI.

**test-engineer** (R8) получает такой же машиночитаемый итог первой строкой — `Status: pass | issues-found | blocked` — и обязанность: написать адверсариальные тесты на изменённую логику, **прогнать** их вместе с существующими наборами из `subteams-tests` и вернуть вывод прогона. `pass` = новые и существующие тесты зелёные.

Режим monkey — без изменений по инструменту (Playwright CLI, воспроизводимость по seed), убрать «VPS has 3.8 GB».

## 8. Риски и нюансы

**Риски**
- **Автоустановка — цепочка поставок** (средняя / высокий ущерб). Митигация: lock-файл в плагине, `npm ci` (сверка sha512 из lock), `--ignore-scripts`, проверка версии бинаря, обновление только релизом плагина после чтения changelog agent-browser, `NO_AUTO_INSTALL`. Chrome — только явной командой.
- **Гейт заклинит работу** в проектах с контрактом (Lightweight-правки, механические массовые замены в UI). Митигация: гейт только при контракте; обход переменной окружения (пользователем); первую неделю смотреть на отказы; если часто — порог по объёму правки.
- **Квитанции «по mtime».** `touch`, переключение веток, `git checkout` файла меняют mtime → лишний отказ (безопасная сторона). Обратное (mtime в прошлом после правки) — только намеренно; гейт — ограничитель модели, не защита от злоумышленника.
- **Стоимость:** каждая UI-правка = все `auto`-наборы + e2e + осмотр. claudebot: e2e 2,6 мин; осмотр — оценка 2-5 мин и 20-50 тыс. токенов sonnet. Правило переиспользования: свежая зелёная квитанция набора (позже последней правки) делает повторный прогон в `finishing-branch` ненужным.
- **Платформа:** `bin/` в PATH субагента, PostToolUse на Bash субагента, транскрипт в SubagentStop — всё закрывает спайк; на каждый «нет» есть план Б (таблица Задачи 0).
- **Эвал недетерминирован:** 5 прогонов не дают точной доли — это сравнение порядка («почти никогда» → «почти всегда»), а не измерение до процента.

**Неочевидное**
- `subteams-tests` ничего не запускает: решение «что гнать» у оркестратора, гейт проверяет только квитанции. Иначе хук гонял бы десятиминутные наборы без спроса.
- Контракт главнее эвристики во всём; без контракта гейт не блокирует никогда.
- `degraded` (осмотр не выполнен по названной причине) пропускается гейтом — честная деградация лучше заклинивания; причина обязана быть в итоговом ответе.

**Зависимости:** `jq` (уже нужен хукам; проверка при старте сессии с явным предупреждением), git, Node/npm (для автоустановки), agent-browser 0.43.0 и его скилл `dogfood`, механизм хуков SubagentStop/PostToolUse Claude Code.

**Откат:** плагин на тег 1.49.0 (правила, хуки, `bin/` вместе); только гейт — `CLAUDE_SUBTEAMS_SKIP_TEST_GATE=1`; только автоустановка — `CLAUDE_SUBTEAMS_NO_AUTO_INSTALL=1`; в проекте — удалить блок-контракт (гейт уходит в режим предупреждений).
