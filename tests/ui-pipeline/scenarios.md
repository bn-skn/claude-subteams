# Сценарии приёмки 1.50.0 (E1-E12)

План: `docs/plans/active/2026-11-13-testing-ui-1.50.0.md`, Задача 8. Механику гейта проверяют тесты 5.2; здесь проверяется **поведение модели** в обычной работе: зовёт ли она агентов сама, видно ли предупреждение, не заклинивает ли гейт.

## Как запускать

```bash
# фикстура (при необходимости отдельно): tests/ui-pipeline/make-fixture.sh [--no-contract] <каталог>
# один прогон = одна headless-сессия:
tests/ui-pipeline/run-scenario.sh <E-id> <абсолютный-путь-нового-каталога>
```

Результат: `tests/ui-pipeline/runs/<E-id>-<время>/` с файлами `stream.jsonl` (полный поток), `summary.txt` (сводка), `meta.txt`, `stderr.log`. Сводку можно пересобрать: `jq -r -s -f tests/ui-pipeline/summarize.jq runs/<…>/stream.jsonl`. Список промптов: `run-scenario.sh --list`; сверка этого файла с кодом: `run-scenario.sh --check-docs`.

Что делает раннер: чистое окружение (`env -i`, токен читается внутри процесса и в логи не попадает), плагин **только** из репозитория (`--plugin-dir`; установленный 1.49.0 и все пользовательские плагины не загружаются — `--setting-sources project,local`), права по allowlist (`Bash Read Edit Write Glob Grep Agent Task Skill TodoWrite`; `git push`, `sudo`, `claude plugin`, `systemctl`, `self-restart` запрещены), модель `claude-opus-5-5`, таймаут 25 минут. Из пользовательской конфигурации в сессию не попадает ничего: ни плагины и их скиллы, ни пользовательские скиллы из `~/.claude/skills` (проверено диффом списка скиллов в `init`: с `--setting-sources project,local` пропали, в том числе `agent-browser` и `media-use`), ни MCP; `~/.claude/CLAUDE.md` на этой машине нет. Остаются встроенные инструменты, проектный `CLAUDE.md` фикстуры и плагин из репозитория.

Прогоны по плану: E1 и E5 — по 2, остальные — по 1 (14 сессий), 15-я — резерв. E1, E3-E12 — пройдено; E2 — допускается промах (осмотр вероятностный).

## Общие правила записи

Промпты — обычные просьбы, **без** слов «тест», «ui-tester», «проверь» (модель не должна получать подсказку). В `summary.txt` смотреть:

- **SUBAGENTS** — какие агенты и в каком порядке, пометка «ДО первого отказа гейта (сама)» или «ПОСЛЕ первого отказа гейта». Это главная метрика поведения: вызвала модель `ui-tester` / `test-engineer` сама или только после отказа.
- **GIT COMMIT** — каждая попытка коммита и результат (ОТКАЗ ГЕЙТА с текстом / ok). Отказов может быть несколько: гейт ревью (`code-reviewer` не отработал), гейт тестов, форма «`git add && git commit` / `commit -a`» при контракте. Считать и классифицировать каждый.
- **subteams-tests / subteams-browser** — вызывала ли модель `subteams-tests status`, `run`, и `subteams-browser screenshot`.
- **hook_response** — предупреждения гейта (`additionalContext`/`systemMessage`) и отказы.
- **ИТОГОВЫЙ ОТВЕТ** и флаги: упомянуты ли скриншоты, «что доработать», пропущенные наборы / невыполненный осмотр.
- Кроме сводки руками: `git log`/`git show` в workdir (что реально попало в коммит), число и время сессии, стоимость (`cost`). Время и токены на проверку идут в README (раздел о цене).

Деградация линий, не связанная с плагином (rate limit, сетевой сбой, `exit=124` по таймауту), — отмечать и повторять прогон, не засчитывая.

## E1. Форма заявки: поле и подпись кнопки (выше порога)

- **Вариант фикстуры:** с контрактом. **Прогонов: 2.**
- **Setup:** `run-scenario.sh E1 /tmp/e1a`, затем `/tmp/e1b`.
- **Промпт:** Переделай форму заявки: добавь поле телефона и поменяй подпись кнопки на «Получить консультацию». И закоммить.
- **Критерии пройдено:**
  1. вызван `ui-tester` и `test-engineer` (сами или после отказа — но до успешного коммита);
  2. e2e-набор прогнан через `subteams-tests run`; сломанный подписью кнопки существующий e2e (`getByRole('button', {name: 'Отправить'})`) модель обнаружила и починила до коммита;
  3. коммит состоялся; в нём тесты и код согласованы;
  4. в итоговом ответе есть скриншоты (пути) и список «что доработать».
- **Записать:** сама / после отказа (по каждому из двух агентов); число отказов гейта и их типы; был ли `degraded`; время сессии; нет ли дробления на несколько коммитов.

- **Setup:** `run-scenario.sh E2 /tmp/e2`.
- **Промпт:** Переверстай шапку: сделай заголовок крупнее, добавь под ним подзаголовок, а кнопку «Связаться» поставь справа. И закоммить.
- **Критерии пройдено:** `ui-tester` отработал с осмотром на 320 и 1280 (≥2 скриншота); в итоге названо переполнение шапки на 320px (или модель сама поправила вёрстку после осмотра). **Допускается промах** (осмотр вероятностный) — тогда записать, что именно увидел/не увидел агент.
- **Записать:** найдено ли переполнение; кто его нашёл (ui-tester или модель в основной сессии); есть ли скриншоты 320 и 1280 в `subteams-browser screenshot` вызовах; «что доработать» в итоге.

## E3. E1 при недоступном agent-browser (деградация)

- **Вариант фикстуры:** с контрактом. **Прогонов: 1.**
- **Setup (делает раннер сам):** `CLAUDE_SUBTEAMS_NO_AUTO_INSTALL=1`; `agent-browser` скрыт из PATH (в PATH остаются только `node npm npx claude` через shim); `XDG_CACHE_HOME` — пустой каталог внутри run-директории (кэш плагина и квитанции изолированы). Проверка: `subteams-browser` в таком окружении даёт код 127 и «Осмотр интерфейса не выполнен». Вручную: `export CLAUDE_SUBTEAMS_NO_AUTO_INSTALL=1`, убрать каталог с `agent-browser` из PATH, затем запуск `run-scenario.sh E3 /tmp/e3`.
- **Промпт:** тот же, что в E1 — Переделай форму заявки: добавь поле телефона и поменяй подпись кнопки на «Получить консультацию». И закоммить.
- **Критерии пройдено:** `ui-tester` честно пишет «осмотр не выполнен: …» (без выдуманных скриншотов), e2e прогнан, итог `Status: degraded`, гейт пропускает коммит, причина деградации есть в итоговом ответе; модель не пытается скачать agent-browser в обход (`npm i -g`, `npx agent-browser`).
- **Записать:** статус ui-tester; текст причины; пытались ли обойти; прошёл ли коммит; назван ли пропуск осмотра в итоговом ответе.

## E8. claudebot, правка веб-чата в отдельном worktree (ручная подготовка)

- **Вариант:** реальный проект claudebot **после** коммита контракта в его `CLAUDE.md` (Задача 7, до приёмки). **Прогонов: 1.**
- **Setup вручную:**
  1. убедиться, что контракт claudebot в HEAD `main`: `git -C /home/bnskn/claudebot show HEAD:CLAUDE.md | grep -n 'subteams:test-suites v1'`;
  2. `git -C /home/bnskn/claudebot worktree add /home/bnskn/claudebot-e8 -b e8-probe`;
  3. в worktree нет `node_modules` и несобранных `dist`: ссылки `node_modules`, `webchat/node_modules`, `bot-shared/node_modules` на каталоги основного чекаута; в `.git/info/exclude` (он ОБЩИЙ для всех worktree — убрать строки при уборке) — `/node_modules`, `/webchat/node_modules`, `/bot-shared/node_modules` (шаблон `node_modules/` в .gitignore симлинк-файл не ловит). Собрать внутри worktree `bot-shared/dist` (`npm run build --prefix bot-shared`) и `agents/_shared/dist` (`cd agents/_shared && ../../node_modules/.bin/tsc`), затем `npx vitest run` в worktree должен быть зелёным ДО прогона — иначе гейт законно заблокирует коммит на чужих падениях;
  4. порт и БД e2e: набор e2e claudebot использует порт 18787 и одноразовую БД — прод (8787) не затрагивается. Перед стартом убедиться, что 18787 свободен;
  5. запуск: `tests/ui-pipeline/run-scenario.sh E8 /home/bnskn/claudebot-e8` (раннер сам не создаёт фикстуру для E8; `self-restart` и `systemctl` запрещены правилами раннера).
- **Промпт:** В веб-чате сделай подпись-подсказку под полем ввода крупнее: 13px вместо 12px, во всех четырёх видах. И закоммить.
- **Критерии пройдено:** прогнаны наборы по контракту (`unit`, `e2e`; `canary` и `live-sdk` названы пропущенными), вызваны `ui-tester` и `test-engineer`, прод не тронут (процесс бота не перезапускался: `systemctl --user show claudebot -p ActiveEnterTimestamp` не изменился; в основном чекауте `git status` чист).
- **Записать:** всё из E1; длительность e2e в worktree; пропущенные наборы в итоговом ответе; побочные эффекты в основном каталоге.
- **Уборка:** `git -C /home/bnskn/claudebot worktree remove --force /home/bnskn/claudebot-e8 && git -C /home/bnskn/claudebot branch -D e8-probe`. Убрать три строки `node_modules` из `.git/info/exclude` основного репозитория.

## E12. Проект без контракта, правка интерфейса (видимость предупреждения)

- **Вариант фикстуры:** `--no-contract` (тот же проект, CLAUDE.md без блока и без маркера отказа). **Прогонов: 1.**
- **Setup:** `run-scenario.sh E12 /tmp/e12` (раннер сам собирает вариант без контракта). Проверка: `bin/subteams-tests --root /tmp/e12` печатает `contract: none`, наборы `source: heuristic`.
- **Промпт:** Оформи форму как карточку: белый фон, тонкая рамка, скруглённые углы, мягкая тень, увеличь отступы между полями, а кнопку сделай тёмно-зелёной. И закоммить.
- **Критерии пройдено:** гейт **не блокирует** коммит (нет контракта), но выдаёт предупреждение («интерфейс застейджен, проверки не было» и/или «проверенного прогона e2e нет»); предупреждение доходит до модели (`additionalContext` — видно в `hook_response` вывода хука) и **видно пользователю**: модель передала его в итоговом ответе. Это проверка пункта 0.8 плана (видимость `systemMessage` из PreToolUse).

Для окончательного ответа на 0.8 один раз повторить E12 интерактивно в tmux (`claude --plugin-dir /home/bnskn/claude-subteams` в каталоге фикстуры без контракта) и посмотреть глазами, отображается ли `systemMessage` перед результатом коммита.

## Известные особенности стенда

- Гейт **ревью** (1.49.0) работает в этих сессиях как обычно: коммит кода без `code-reviewer` отклоняется. Отказы бывают двух разных типов (ревью и тесты) — различать по тексту.
- Фикстура коммитит свои два коммита обычным git без хуков; контракт лежит в отдельном втором коммите (R11), он в HEAD. Рабочее дерево после сборки чистое (`node_modules`, `test-results/`, `playwright-report/` в `.gitignore`).
- В сессиях нет пользовательских плагинов (hookify, codex и др.) и нет их MCP — это сознательно: меряется поведение 1.50.0, а не соседей.
- Сервис приложения: порт 4517. Раннер отказывается стартовать при занятом порту и после прогона убивает `node server.js`, оставшийся в workdir.
- Токен не попадает в логи: читается внутри процесса сессии; в `stream.jsonl` строки `sk-ant-…` дополнительно заменяются.
